# research-credit-settlement

科研成果工作量的周期结算库。在作者周期上限封顶后，把每项成果的预算拆分为
署名作者的整数积分，并同时满足成果、（作者, 指标）组合、指标三个层面的汇总
取整约束——不因逐项舍入让作者超限或凭空增加积分。

一个积分单位表示 0.01 工作量分。

## 使用

```bash
npm install
npm test
```

```ts
import { settle } from "research-credit-settlement";

const out = settle({
  works: [
    { id: "w1", indicator: "论文", budget: 100, authors: ["甲", "乙"] },
  ],
  // 甲未封顶份额 200/3 超过上限 60，封顶到 60；乙 100/3 不封顶。
  // 成果合计 ⌊280/3⌋ = 93，指标合计 round(280/3) = 93。
  caps: [
    { author: "甲", indicator: "论文", cap: 60 },
    { author: "乙", indicator: "论文", cap: 60 },
  ],
});
// out: [{ workId: "w1", shares: { 甲: 60, 乙: 33 } }]
```

## 结算规则

1. **未封顶份额**：一项成果有 n 名作者，第 i 位（从 1 开始）权重为 n-i+1，
   未封顶份额 = P × 权重 / 权重之和。
2. **封顶缩放**：对每个（作者, 指标）组合，若未封顶份额之和 S 超过周期上限 C，
   该组合所有份额同时乘以 C/S；被扣掉的积分不转给其他作者。所得精确有理数
   份额记作 x。
3. **整数分配 z**（通过带下界的可行流同时满足）：
   - 每个（成果, 作者）单元格：z ∈ {⌊x⌋, ⌈x⌉}，未署名作者不得分积分；
   - 每项成果：z 之和 ∈ {⌊Σx⌋, ⌈Σx⌉}；
   - 每个（作者, 指标）组合：z 之和 ∈ {⌊Σx⌋, ⌈Σx⌉} 且不超过 C；
   - 每个指标：z 之和 = round(Σx)，恰好半单位时向上取整，指标之间不借分。

## 实现要点

- 全部份额以 BigInt 有理数精确表示（`src/rational.ts`），不存在浮点误差。
- 封顶缩放在 `src/shares.ts` 完成。
- 取整问题建模为可行循环流：源 → 成果 → （作者, 指标）组合 → 指标 → 汇，
  每条边的下/上界即对应层面的向下/向上取整；由于所有界都是整数，无需任何
  放大，单元格流量自然落在 ⌊x⌋ 或 ⌈x⌉ 上。求解器为 Dinic 最大流
  （`src/flow.ts`），组装在 `src/settle.ts`。
- 输入非法（负预算、重复成果 ID、重复作者等）或约束不可满足时抛出异常。
