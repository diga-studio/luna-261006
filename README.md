# ap-aging-ledger

应付账款历史账龄库（TypeScript，纯进程内存）。由上层财务系统直接以库的方式调用，
不包含接口层与持久化。

## 能力

- `appendBatch(batch)`：追加入账批次。批次整体生效，返回连续递增的修订号（1, 2, 3, …）。
  批次可包含新发票、部分核销、核销冲回。
- `queryAging(reportDate, revision)`：按报表业务日 + 可见修订号查询账龄汇总。
  只使用不晚于该修订的记录；同一组查询条件永远得到相同结果，旧修订不受后续追加影响。

```ts
import { AgingLedger } from "./src";

const ledger = new AgingLedger();
const r1 = ledger.appendBatch({
  invoices: [{ id: "inv-1", currency: "USD", amount: "100", invoiceDate: "2024-01-01", dueDate: "2024-01-31" }],
});
const r2 = ledger.appendBatch({
  payments: [{ invoiceId: "inv-1", amount: "40", date: "2024-02-05" }],
});
ledger.queryAging("2024-02-10", r1).currencies["USD"].overdue1To30; // "100"
ledger.queryAging("2024-02-10", r2).currencies["USD"].overdue1To30; // "60"
```

## 规则要点

- 日期为 `YYYY-MM-DD` 公历日（2000–2099），当天发生的记录计入当天。
- 金额为最多 4 位小数的十进制数（建议传字符串），返回值是十进制字符串，累计精确。
- 发票录入后不修改；核销减少、冲回增加未付余额，均从各自业务日起生效，不追溯改写。
- 尚未开票（开票日晚于报表日）的发票不参与统计；零余额不贡献金额。
- 分桶：未到期及当天到期 → `current`；逾期 1–30 / 31–60 / 61–90 天 → 对应桶；
  超过 90 天 → `overdue90Plus`。同一发票的全部余额归入同一桶。
- 结果按币种分别返回全部可见币种的五桶余额，不做汇率换算。

## 设计简述

- 发票/核销/冲回统一为带符号金额的"事件"（发票 +、核销 −、冲回 +），
  事件携带发票的到期日与币种。
- 对报表日 D，桶边界只依赖 `due <= D - c`（c ∈ {1, 31, 61, 91}），因此每个事件预计算
  5 个排序键 `key = max(date, due + c)`，把五桶汇总化为每个（币种 × 键）上的
  二维前缀和（修订号 ≤ R 且键 ≤ D）。
- 事件按修订顺序追加；连续修订封存为不可变块，块内按（币种 × 键）存排序键与前缀和，
  整块用二分查找回答；跨界块扫描其按修订有序的记录前缀；未封存的尾部直接扫描。
  追加均摊 O(log n)，查询 O(块数 × 币种 × 5 × log + 一个块的扫描量)。
- 金额按 10^4 缩放为整数单位；累计量级（10 万亿 × 10^4 = 10^17）超过 2^53，
  热路径用 hi/lo 双浮点分量精确累计，最终经 BigInt 合成，保证十进制精确。

## 构建与测试

```sh
npm install
npm test
```

只需要 Node.js 与 npm；TypeScript 编译器在 `devDependencies` 中声明。
测试覆盖：验收场景（晚录入核销/冲回、旧修订不变）、分桶边界（到期当天与
30/60/90 天两侧）、随机复杂流水与逐笔暴力计算对拍，以及规模测试
（5 万发票、15 万核销/冲回、25 币种、20 万+ 修订、1 万轮交替追加与查询、
峰值内存上限 768 MiB）。
