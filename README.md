# 房源重复候选检索库

供上层清洗流水线直接调用的进程内库：装入一份房源目录后，为每条新房源检索目录中的全部重复候选。本模块只做候选检索，不执行合并；目录与检索状态只保存在进程内存，装入后不再修改，查询无副作用。

## 构建与测试

只依赖 Node.js 与 `package.json` 中声明的开发依赖（TypeScript）：

```bash
npm install   # 安装 typescript（devDependency）
npm test      # 编译并运行全部自动化测试
npm run perf  # 运行两类 10 万条规模的性能样例
```

## 使用

```ts
import { loadCatalog } from "./src/index.js";

const catalog = loadCatalog([
  { id: "r1", address: "北京市朝阳区建国路1号", description: "精装修拎包入住" },
  // ...最多 10 万条
]);

// 阈值范围 0.70~1.00，最多两位小数；非法阈值抛 RangeError
const hits = catalog.findDuplicates(
  { id: "q1", address: "北京市朝阳区建国路1号", description: "精装修可拎包入住" },
  0.9,  // 地址阈值
  0.8,  // 描述阈值
);
// hits: 命中记录的 id 数组，按装入顺序；同一文本对应多个 id 时分别保留
```

## 规则与语义

- 相似度 = 1 − Levenshtein 编辑距离 / 两侧码点长度的较大值；长度与编辑单位均为 Unicode 码点（非 BMP 字符算 1 个单位），插入/删除/替换代价均为 1，相邻交换不算一次编辑。两侧均空串相似度为 1，仅一侧为空串为 0。
- 地址与描述分别计算相似度，两者均达到各自阈值（含恰好相等）才算重复候选。判定用整数有理数比较（`100·(M−d) ≥ t·M`），不做四舍五入。
- 输入文本假定已完成 Unicode NFC 规范化，本模块不改动大小写、标点或空白。

## 实现要点

- `src/levenshtein.ts`：码点级 Levenshtein；`boundedDistanceCP` 为带上限的条带 DP（超出上限提前终止），用于阈值判定。
- `src/gramIndex.ts`：每个字段一份 q-gram（q=3）倒排索引。查询先用长度过滤 + q-gram 计数引理（`ed≤k ⇒ 公共 q-gram 数 ≥ max(len)−q+1−k·q`）做安全预过滤（只去伪、不丢真），候选再做精确 DP 判定。计数下界 ≤0 的短串情形有专门回退扫描，保证完备性。纯 BMP 文本的 gram 编码为 48 位数值键，装入两遍扫描、精确分配倒排数组，控制内存与装入耗时。
- `src/catalog.ts`：阈值校验（百分制整数化）、按查询选择倒排代价更小的字段驱动检索、另一字段逐对验证。

## 性能样例（`npm run perf`，10 万条目录）

- 样例 A：地址高度重复（约 50 条记录共享同一地址）、描述随机有区分度。
- 样例 B：描述复用 50 个模板、地址逐条随机有区分度；含构造的近重复簇。
- 两个样例地址中位长度 ≥40 码点、描述中位长度 ≥160 码点；预期命中由生成器按构造给出，另对前 10 条查询做全目录逐对精确计算独立核对。
- 报告装入耗时、1000 条查询（阈值均 0.80）累计耗时、驻留内存峰值（heapUsed+external）与进程 rss 参考值。注意：macOS 的 rss 包含内核可回收的 MADV_FREE 页，会显著高于实际驻留内存；在 Linux 上 rss 与驻留值接近。本机实测：装入 ≤10s，查询累计 ≤3.5s，驻留峰值 ≤220MiB（预算分别为 60s / 30s / 512MiB）。
