# prepaid-revenue-ledger

预付订阅收入封账库（TypeScript + SQLite）。上层直接调用，只提供三类能力：
批量录入（预付款项目 / 退款）、推进封账、区间导出。

## 要求

- Node.js >= 22.5（使用内置 `node:sqlite`，无任何原生或运行时依赖）
- `npm install` 后 `npm test` 即可运行全部测试

## API

```ts
import { RevenueLedger } from 'prepaid-revenue-ledger';

const ledger = new RevenueLedger('ledger.db');

// 批量录入预付款项目：标识、原金额（整数分，bigint）、服务起止日期（UTC 整日，起含止不含，1..3650 天）
ledger.ingestItems([{ id: 'sub-1', amount: 12000n, startDate: '2024-01-01', endDate: '2025-01-01' }]);

// 批量录入退款：可提前登记、可不按生效日期顺序、同日多笔按合计处理
ledger.ingestRefunds([{ itemId: 'sub-1', amount: 3000n, date: '2024-06-01' }]);

// 推进封账截止日（只能向前，已封结果不可变；封账后仍可登记未来退款）
ledger.closeTo('2024-12-31');

// 导出已封区间：每日收入、每日递延余额、区间收入合计
const report = ledger.exportRange('2024-01-01', '2024-12-31');
```

所有金额均为 `bigint` 整数分，单笔上限 10^18 分；汇总值可远超 `Number.MAX_SAFE_INTEGER`，
全程精确计算。日期为 ISO `YYYY-MM-DD`（UTC 整日）。

## 确认规则

对任意日期：C = 原金额 − 截至当日已生效退款，D = 原服务天数，k = 截至当日已经历服务天数（0..D）。
应累计确认额：k=0 时为 0；k=D 时为 C；其余为 `floor(C/D) * k`（日额按分向下取整，尾差归最后一天；
退款后按净额重算应累计确认额）。当日收入 = 当日与前一日应累计确认额之差（可为负）。
期末递延余额 = 截至当日已生效预付款 − 退款 − 累计确认额；服务结束后的退款在生效日冲减收入。

## 设计

- 单个项目的每日收入在相邻退款生效日之间是分段常数，因此每个项目只产生 O(退款数) 个
  按日差分事件（费率差分 / 一次性调整 / 预付款 / 退款流），见 `src/schedule.ts`。
- 账本把全部项目的事件汇总到四张按日索引的全局表；封账即按日扫线，
  每日收入 = 当日费率 + 一次性调整，递延余额由预付款、退款、累计收入推出，见 `src/ledger.ts`。
- 业务事件与已封每日结果都持久化在 SQLite（金额以 TEXT 存 bigint）；封账截止日只前进，
  已封结果不可变。每日结果是业务事实的纯函数，与退款录入顺序、批次、封账分段无关。
- 复杂度：录入 O(事件数)，封账 O(天数)，导出 O(区间天数)；内存与事件数成正比，与项目×天数无关。

## 测试

`npm test` 编译后运行：

- `test/small.test.ts`：以独立的逐项目逐日计算为基准，覆盖乱序退款、同日拆分退款、
  最后服务日尾差、服务结束后全额退款、恒等式（预付款 − 退款 = 累计收入 + 递延）、
  一次封账与多次推进逐日一致、输入校验、重开库后继续推进。
- `test/scale.test.ts`：30 万项目（24 万笔 3650 天）+ 60 万退款 + 连续 30 年，
  一次性封至末日与逐日推进（含分批、生效日期交错的未来退款）两种模式各自在独立进程执行，
  断言每种模式录入+封账 ≤ 60s、峰值 RSS ≤ 512 MiB、数据库文件 ≤ 512 MiB；
  两模式完整日报逐日一致，并在抽查日期用独立逐笔计算核对收入与递延余额。
