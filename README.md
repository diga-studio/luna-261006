# task26100614

流式拆帧库（Go）。线格式：`A5 5A` 同步字 + 2 字节大端载荷长度 + 载荷 +
2 字节大端 CRC16/CCITT-FALSE（覆盖长度字段与载荷）。

API：`Encode(payload)`、`Decoder.Feed(chunk)`、`Decoder.Finish()`。
帧携带自流起点计数的字节偏移与原始载荷（私有拷贝，后续调用不会改写）。

## 复杂度依据

- 总工作量 O(n log L)：每字节追加时 O(1) 更新零初值 CRC 前缀状态；
  同步字搜索总量摊还 O(n)（`bytes.Index`，被跳过的字节不会重扫）；
  每个完整候选的 CRC 用前缀状态 + A^k 矩阵快速幂做 O(log L) 窗口查询，
  候选数 O(n)，故 CRC 总量 O(n log L)，不对任何候选重扫其载荷。
- 额外空间 O(L)：缓冲区只保存一个不完整候选（≤ 65541 字节）加一个
  噪声扫描块（32 KiB），预分配约 295 KB，远低于 1 MiB；单次 Feed
  再大也按块消化，不缓存完整输入流。

## 验证

`go test ./...`：CRC 校验向量与逐位参考对照、窗口 CRC 对照直接 CRC、
三类嵌套/截断语义、随机小流对照独立参考解析器（单字节/随机/整块三种
分块结果一致）、16 MiB 压力流（每 32 字节一个声明近最大长度的候选，
绝大多数完整候选直到 CRC 才失败，夹入 64 个有效帧）。

`go test -bench . -benchmem`：压力流约 104 MB/s，每次迭代内部额外
分配约 0.6 MB（含一次性缓冲与输出帧拷贝）。
