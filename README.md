# sentinelvault-crypt

供 SentinelVault 上层调用的原地文件加密库：文件保留在本地原路径，
任务记录存 SQLite，进程在任意时刻被终止后均可凭批次标识与密钥续跑。

## 能力

- `vault.submit({ batchId, files, key })`：提交新批次或续跑既有批次。
  同一 `batchId` 的重试必须使用相同清单与密钥（库用清单与密钥指纹校验，
  不持久化密钥本身）。
- `vault.progress(batchId)`：查询批次进度。完成状态以磁盘实际内容为准
  （识别本批次密文信封头），与任务记录无关。
- `vault.readPlaintext(batchId, key, path)`：验证完整性（AES-256-GCM）后
  读回已完成文件的本批次原始字节；验证失败抛出异常，不返回任何明文。

## 崩溃安全保证

- 单文件：写同目录临时文件 → fsync → 原子 rename → 记录完成。
  任意时刻终止，目标路径只会是完整原文或本批次完整最终密文。
- 续跑：已是本批次最终密文的文件逐字节保留、绝不再加密；
  写了一半的候选密文临时文件（`.svltmp-*`）会被清理并重做。
- 整批完成时，目录中不遗留原文副本、候选密文或废弃临时文件；
  批次记录保留在 SQLite 中用于识别重试。

## 限制

- 每批最多 500 个文件，每个文件最大 8 MiB，任务串行执行。
- 输入为路径固定、无硬链接/符号链接的普通文件。
- 密钥为 32 字节 `Buffer`，由调用方保管，库不持久化。

## 构建与测试

```sh
npm install
npm test
```

仅依赖 Node.js（>= 22.5，使用内置 `node:sqlite`）与 TypeScript，
无原生模块、无外部服务。
