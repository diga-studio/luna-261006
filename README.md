# dem-cut-fill

本地 DEM 挖填量计算库（TypeScript / Node.js）。输入均使用同一米制平面坐标系，网格轴向一致。

## 使用

```bash
npm install
npm test        # 编译并运行全部测试
npm run build   # 仅编译到 dist/
```

```ts
import { writeDEM, compareDEMs } from 'dem-cut-fill';

// 写入 DEM：rows 为异步行流，每行是长度为 width 的 Float64Array，共 height 行
await writeDEM(directory, { width, height, x0, y0, step }, rows);

// 比较两份 DEM
const { area, cut, fill } = await compareDEMs(oldDirectory, newDirectory);
// area：共同有效面积，平方米
// cut / fill：挖方量 / 填方量，立方码（1 码 = 0.9144 米，严格换算）
```

## DEM 格式

每个 DEM 是本地一个目录：

- `meta.json`：`{ width, height, x0, y0, step }`。`width`/`height` 为节点数，
  `(x0, y0)` 为左下角节点坐标，`step` 只支持 0.5 / 1 / 5 / 10 米。
- `elevation.bin`：按行排列的小端 Float64 节点高程（米），行沿 y 增大方向、
  列沿 x 增大方向，`NaN` 表示 NoData。节点不是像元中心。

一个单元由相邻四节点围成，仅当四角均非 NoData 时有效；单元内部高程严格为
四角值的双线性插值。`writeDEM` 先写 `elevation.bin`、最后写 `meta.json`，
因此存在完整的 `meta.json` 即表示数据写完。

## 算法

1. **比较域**：两份 DEM 覆盖矩形的交集。把两份网格落在交集内的所有格线合并，
   得到一组子矩形；每个子矩形完整落在两份 DEM 各自的某个单元内。子矩形计入
   比较域 D 当且仅当两个对应单元都有效（四角非 NoData）。半格级重叠由此自然
   计入，且不向无效单元或网格外插值。
2. **挖填积分**：在子矩形上，旧、新表面都是双线性函数，差值 d = 旧 − 新 仍为
   双线性函数。挖方 = ∫max(d,0)，填方 = ∫max(−d,0)，两者逐子矩形独立累计，
   任何位置互不抵消，同一单元内部可同时有挖方和填方。
3. **正部积分**：固定 x 时双线性函数关于 y 是线性的，其正部对 y 的积分有精确
   闭式解；外层对 x 用自适应 Simpson（Richardson 误差估计）积分。零线（双曲线）
   穿过子矩形时由自适应细分自动逼近。

## 数值误差控制

- 允许步长 0.5/1/5/10 均可被二进制浮点精确表示，格线坐标为 `x0 + i*step`
  的单次乘加，无累积误差；合并格线只在 1e-9×step 容差内去重，遗漏的条带
  宽度不超过该量级。
- 有效面积为子矩形面积的直接求和，是精确算术。
- 内层积分（关于 y）为闭式精确解；外层自适应 Simpson 以 Richardson 外推
  估计误差，容差 1e-12（按子矩形尺度与角点幅值缩放），单个子矩形积分误差
  约 1e-12 相对量级。解析测试（含 ln(4) 项）的实测误差为 0（机器精度）。
- 体积换算严格使用 1 码 = 0.9144 米（0.9144³ 精确可表示）。

## 测试

`test/dem.test.ts`：

- **解析验证**：单位正方形上旧面为 0、新面为 x·y−0.25（xy 是双线性函数，
  插值精确）。有效面积 1 平方米，挖填量均为 (3+2·ln4)/64 立方米换算值。
- **构造网格**：旧网格 step=1、含内部 NaN；新网格 step=0.5、原点 (0.25,−0.5)
  不对齐、含内部 NaN，新表面为平面 z=x−1.3。手算得比较域
  [2,2.25]×[0,1] ∪ [0.25,2.25]×[1,1.5]，面积 1.25 平方米，挖方 0.275625、
  填方 0.431875 立方米。覆盖部分单元重叠、无效单元排除、输入交换
  （交换后面积不变、挖填互换）。
- 无共同有效区域（区域不相交 / 一方全 NoData）时三个结果均为 0。
- `writeDEM` 对非法 step、行宽不符、行数不符的输入抛错。
