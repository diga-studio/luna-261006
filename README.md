# 采购批次召回库

在 Node.js 上以 TypeScript 实现的批次召回精确追踪组件。输入是入库、拆分拼箱、
生产混料的只读历史；本组件只负责追踪，不实现库存交易。

## API

```ts
import { buildIndex, recall } from './src/recall';

const index = buildIndex(records);        // 接收全部历史，返回可重复查询的索引
const result = recall(index, ['A', 'B']); // Map<批次ID, 有序不重叠且相邻已合并的区间[]>
```

- 记录不必按依赖顺序给出；建索引后历史不再修改，索引可反复查询。
- 批次内部数量用从 0 开始的左闭右开区间表示，全程以区间运算处理，
  不逐单位展开，资源消耗与实物数量（可达 1 万亿）无关。
- `recall` 可选第三个参数 `stats`，返回本次查询的访问计数
  （触及批次数、传播片段数、引用二分查找次数、命中引用条数），用于开销核验。

## 历史模型

- `intake`：原始入库，只有批次 ID 与数量。
- `repack`（拆分拼箱）：有序输入列表，新批次按顺序连续拼接各父区间，
  位置映射保持区间内部顺序，只是搬运。
- `mix`（生产混料）：任一**实际投用**区间含污染则产出全部受污染；
  未投用部分的污染不触发传播；产出数量可与投入不同。

## 实现与查询开销

索引为每个父批次保存按起点排序的后续取用引用表（同一父批次的取用区间
互不重叠，可二分查找）。查询从源批次出发做**增量区间传播**：

- 每个批次本地维护一个有序合并的污染区间集合；只有新到达的 delta
  片段会被向下游推送一次，多次汇合的污染在本地合并，**不按路径枚举**。
- 每个 delta 片段在父批次引用表中做一次二分查找，只访问与之相交的
  引用，跳过不相干的海量取用；不扫描全部历史记录。

设一次查询产生的污染片段总数为 P（每个片段对应结果中某批次的一个区间
或后来被合并掉的片段），命中引用数为 H，则查询开销为
`O(P · log R + H)`，其中 R 为单个父批次的引用数；与批次总数、实物数量、
源到目标的路径数均无关。`test/scale.test.ts` 用访问计数断言了这些性质：

- 万亿级数量的 2000 环长链：工作量与环节数成正比，不展开单位；
- 60 轮拆分再汇合（路径数 2^60）：传播片段数随层数线性增长；
- 5 万条不相交取用中的微小污染：只 2 次二分、命中 2 条引用，
  另混入 10 万个无关批次验证查询不做全量扫描。

## 测试

```sh
npm install
npm test
```

只依赖 `typescript` 一个 devDependency；编译后用 Node 内置测试运行器执行：

- `test/exact-chain.test.ts`：跨供应商拼箱、跨边界拆分、小段混料的逐层精确区间；
- `test/scale.test.ts`：万亿数量、汇合路径爆炸、巨型批次稀疏取用的访问计数；
- `test/random.test.ts` + `test/reference-model.ts`：300 组随机合法小历史
  与独立逐单位参考模型对照，覆盖多召回源、空交集、端点相接合并。
