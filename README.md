# frameproto

流式拆帧库：从含噪声、截断帧、损坏帧的字节流中提取有效报文。
只做拆帧与 CRC 校验，载荷保持原始字节。

## 线格式

```
+------+------+---------+---------+----------+---------+
| 0xA5 | 0x5A | len(MSB)| len(LSB)| payload  | CRC(MSB,LSB) |
+------+------+---------+---------+----------+---------+
```

- 载荷长度：两字节无符号大端，0–65535。
- CRC：CRC16/CCITT-FALSE（多项式 0x1021，初值 0xFFFF，不反射，异或值 0），
  覆盖长度字段与载荷，不覆盖同步字与 CRC 字段。

## API

```go
frame, err := frameproto.Encode(payload)   // 编码一帧
d := frameproto.NewDecoder()
frames := d.Feed(chunk)                    // 任意大小分块，返回本次确定的帧
last  := d.Finish()                        // EOF，返回剩余可确定的帧
```

`Frame.Offset` 为从流起点计数的字节偏移；`Frame.Payload` 为独立副本，
后续调用不会改写已返回的载荷。Decoder 非并发安全。

## 拆帧语义

- 从当前扫描位置找最早同步字形成候选；候选完整且 CRC 正确则输出整帧，
  从帧末继续（帧内同步字不再解释）。
- 完整候选 CRC 错误时只排除该起点，向后找下一个同步字
  （损坏候选内部的有效帧仍可输出）。
- Feed 中最早的候选尚未完整时必须等待，即使其内部已有完整有效帧；
  Finish 把不完整候选视为失败，继续检查其内部及后续候选。
- 同一有限流无论如何分块，Finish 后输出的帧、顺序、偏移完全一致。

## 复杂度依据

设 n 为流长度，L 为最大帧长（本格式 65541）。

- **时间 O(n log L)**：
  - 每个输入字节 O(1)：写入环形缓冲并更新前缀 CRC。
  - 同步字扫描摊还 O(1)/字节：扫描指针单调前进，每字节至多被检查一次。
  - 候选总数 ≤ n/2（每个候选对应一个不同的同步起点）。每个候选的 CRC
    通过前缀 CRC 的线性组合在 O(log L) 内求得，**不重扫载荷**：
    CRC 寄存器更新在 GF(2) 上是仿射的，
    `F(M, I) = F(M,0) ^ T_|M|(I)`，其中 `T_k` 为"推进 k 个零字节"的
    线性映射（预先分解为 18 个 16×16 位矩阵，按 k 的二进制位组合）。
    于是区间 `[a,b)` 的 CRC =
    `P0(b) ^ T_(b-a)(P0(a)) ^ T_(b-a)(0xFFFF)`，
    `P0` 为初值 0 的前缀 CRC。该性质在 `crc16_test.go` 中与直接逐字节
    计算做了随机对拍。
- **额外空间 O(L)，实测约 384 KiB（< 1 MiB）**：
  解码器只持有两个固定大小的环形缓冲（数据 128 KiB + 前缀 CRC 256 KiB）。
  缓冲起点 = 当前最早候选起点，单调前进；候选不完整时窗口 <
  候选声明长度 ≤ L，候选完整时立即处理并收缩，因此窗口恒有界，
  不缓存完整输入流，单次 Feed 可任意大。返回帧的载荷副本属于结果，
  不计入内部内存。

## 验证

```
go test ./...                 # 全部单元/语义/随机对拍/16 MiB 压力测试
go test -bench . -run '^$'    # 基准
```

- `decoder_test.go`：CRC 错误外层候选包住有效内层帧（含输出时机）、
  CRC 正确外层帧包住同步字、EOF 截断候选包住完整有效帧。
- `reference_test.go`：独立离线参考解析器对拍随机小流；单字节、
  随机分块、一次性输入结果一致；同步字/长度/CRC 边界的所有切分点。
- `stress_test.go`：≥16 MiB 压力流，每 32 字节一个声明最大长度的候选，
  绝大多数候选直到 CRC 判定才失败，夹入 256 个有效帧；用测试内
  独立实现的区间 CRC 预言机核对，并报告耗时与内存。

本机实测（Apple M1 Max）：压力流解码约 90 MB/s，
解码器静态内存 393,280 字节，单次 Feed 1 MiB 分块下
总分配增量约 0.4 MiB（含返回载荷）。
