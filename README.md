# batch-recall

采购批次召回库（TypeScript / Node.js）。输入是入库、拆分拼箱、生产混料的只读历史，
负责把“受污染的原始入库批次”精确传播到所有受影响批次，输出每批次的受影响数量区间。
不实现库存交易。

## 使用

```ts
import { buildIndex, recall } from 'batch-recall';

const index = buildIndex(records);        // 全部历史，顺序任意，建后不可变
const affected = recall(index, ['B001']); // Map<批次ID, 有序不重叠的区间[]>
```

记录类型（`src/types.ts`）：

- `receipt`：原始入库，`{ batchId, quantity }`。
- `repack`：拆分拼箱，`inputs` 有序，新批次按顺序连续拼接各父批次区间。
- `mix`：生产混料，任一实际投用区间含污染则产出整批受污染，数量可与投入不同。

区间均为基于 0 的左闭右开整数区间，数量最大 1 万亿（远小于 2^53，用 number 精确表示）。

## 索引与查询开销

设 N = 批次数，E = 输入引用总数。

- **buildIndex**：Kahn 拓扑排序 + 按父批次归集取用引用并排序，`O(N + E log E)` 时间、
  `O(N + E)` 空间。只存区间端点，与批次实物数量无关，万亿级数量不展开。
- **recall**：按拓扑序的最小堆前向传播。每个受污染批次恰好处理一次，
  处理前先把到达的污染区间排序合并——多条传播链汇合时合并后统一下传，
  工作量与路径条数无关（指数级路径的菱形汇合也只花线性时间）。
  对每个污染区间，在父批次有序的取用引用数组上二分定位首个相交引用，
  只扫描实际相交的引用，不相交的大量后续取用被直接跳过。
  总开销 `O(K log K + Σ 相交引用数)`，其中 K 为本次传播实际触及的批次数；
  不扫描全部历史，也不枚举源到目标的路径。
- **正确性性质**：多源查询 = 分别查询后逐批次取区间并集（堆按拓扑序弹出，
  父批次所有污染区间先于子批次处理完毕，汇合不丢失）；结果区间有序、
  不重叠、相邻已合并；混料只由实际投用区间触发，未投用部分不传播。

`recall` 接受可选的第三参数 `RecallStats`，回填 `visitedBatches` 与
`scannedUsages`，测试据此断言无全量扫描、无路径爆炸、无逐单位展开。

## 测试

```sh
npm install
npm test
```

只依赖 devDependency `typescript`（编译）与 Node.js 内置 `node:test`（运行），
干净机器上 `npm install` 后 `npm test` 即可跑通。

- `test/recall.test.ts`：跨供应商拼箱、跨来源边界拆分、小段混料的逐层精确区间断言。
- `test/scale.test.ts`：万亿级数量、指数级路径汇合、5 万条不相交取用、10 万批次
  线性扩展，用 `RecallStats` 核对访问规模。
- `test/model.test.ts`：200 个种子的随机合法小历史，与测试中独立实现的逐单位
  参考模型对比；覆盖多源、空交集、端点恰好相接。
